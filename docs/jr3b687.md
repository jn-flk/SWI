### F1
**Source:** C02

**Engineering claim:** The C02 specification (operations.md OP-01/OP-03, intent_and_change.md, BR-04/BR-07/BR-08, activity and state diagrams) defines the behaviour of Create/Confirm, and the implementation + tests are said to realise it (EE:55, EE:58-97).

**Expected:** Document the 15-minute cutoff, 24-hour bulk-reservation lead time at Create and Confirm, and hold renewal in operation conditions, rule references and diagrams.

**Observed:** Code and tests implement these rules, but OP-01/OP-03 omit some conditions; OP-03 does not reference BR-08; activity/sequence/state/use-case diagrams omit checks or renewal. BR-07 describes five-minute expiry but not renewal, and C01's cutoff lacks a C02 rule ID. EE:137-138 acknowledges diagram omissions.

**Verification:** Compared code/tests with specification and diagrams; behaviour is implemented but incompletely specified. Suite not executed (B2). **Result: VERIFIED FINDING.**

### F2
**Source:** C03

**Engineering claim:** ADR-01 (outbox, notification recorded in the same transaction, asynchronous delivery) is the accepted decision, and the C03 architecture views and conformance checks are consistent with it (EE:179-181, EE:199-207, EE:233-244).

**Expected:** Architecture views and conformance evidence should reflect ADR-01's transactional outbox and separate dispatcher, or be marked historical; the cited conformance test should exist.

**Observed:**
1. `_notify` calls `record_notification` inside the transaction; no `on_commit` exists.
2. G2/H1 still describe post-commit notification, G4 omits the dispatcher, and EE:179-181 still describes the ADR as post-commit. EE:384-385 calls the original C03 `on_commit` description a historical baseline replaced by C05, but these C03 views carry no such mark.
3. `reservation/notifications.py` is an unused compatibility shim. Logging is imported by `notification/adapters.py` and `dispatcher.py`, not that shim.
4. The claimed `test_notification_side_effect_is_isolated_to_integration_adapter` is absent from `reservation/tests.py`, and its stated premise is obsolete.
5. ADR-01 says dispatch can join the expiry watch loop with no new deployable (AD:286, 346), but `dispatch_notifications --watch` is a separate command.

**Evidence:** G2/G4/H1 and `c05-notification-outbox.png`; AD:56-59, 79, 286, 307-365, 525-534; EE:179-181, 222, 233-244, 384-387; `reservation/services.py:126-127, 231`; expiry command; notification adapters/dispatcher.

**Verification:** Traced call path and searched for `on_commit`, shim importers, logging imports and the named test. Suite not executed (B2). **Result: VERIFIED FINDING.**
